# Simple Run — 試作設計 v0.1

## 目的と範囲
スマホ縦画面で遊ぶ、無表情な白いマネキンのエンドレスラン。横へ滑るように動き、箱と奈落を避け続ける。見た目とUIは極力簡素。最終公開先はGitHub / GitHub Pagesを想定し、今回はローカルで動く静的Webゲームまで実装する。

## 確定要件
- 完全な直線、平坦、一定幅。コース幅はマネキンの肩幅の5倍。
- 自動で前進。左右は自由なドラッグ操作。常に正面を向き、横移動で旋回・傾斜しない。ジャンプなし。
- コース外へは出ない。端では透明な境界に止まる。可視の壁は置かない。
- 箱は固定。奈落は実際に床が欠ける。どちらも幅と左右位置を変える。
- 必ず通れる幅を残し、連続した障害物も移動可能な組み合わせのみ生成。
- 箱は見た目より少し広い接触判定。奈落は足元で判定し、箱と同じ余白を加えない。
- 距離とともに速度・操作頻度が増す。遠方を見て先読みできる。
- 3 / 2 / 1 / Run!。開始は低く近いカメラ、走り出しに通常の追従カメラへ移行。
- 箱への衝突で転倒、奈落で落下。走行距離・自己ベスト・リトライのみ表示。再挑戦は次のカウントダウンへ直行。
- 説明文、チュートリアル文章、アイテム、レーン、ボイス、広告、オンラインランキングなし。

## 操作
画面のどこからでもドラッグ可能。タッチ開始位置からの相対変位で横位置を指定し、指を置いた場所への瞬間移動を防ぐ。画面上の指の移動量とrunner胴体の移動量を1:1に換算し、速度制限や平滑化なしで直接反映する。指を離すとその横位置を維持。生成では人間の操作余裕を保つため想定横移動速度5.4/秒を使う。主ポインタ1本のみ受け付け、スクロールやズームを抑制。タッチキャンセル時は現在位置で停止。マウスドラッグも開発確認用に同じ処理。

## 基準値（要実機調整）
| 項目 | 初期値 |
|---|---|
| 肩幅 / コース幅 | 0.6 / 3.0 |
| runner半幅 / 箱判定の追加余白 | 0.30 / 0.03（片側） |
| 最小通路幅 | 0.84（肩幅の約1.4倍） |
| 生成で想定する横移動速度 | 5.4 / 秒（操作自体に速度制限なし） |
| 前進速度 | 8 + 経過秒 × 62 / 120、上限70（120秒で到達） |
| 見通し | 常に約4秒先。霧は遠方だけ薄く隠す |
| 最初の障害物 | 走り出して4秒後に到達 |
| 障害物の前後長 | 到達時速度 × 0.18〜0.28秒 |
| 序盤の到達間隔 | 1.8〜2.4秒 |
| 中盤の到達間隔 | 1.0〜1.5秒（250m時点） |
| 高難度の到達間隔 | 0.6〜0.9秒（900m以降） |
| 操作余裕 | 前の障害物を抜けてから必要移動時間に加え0.18秒 |

速度は上限まで増加。操作頻度は900mで上限。両者は別のパラメータとして扱う。最初の2個は箱、以降は奈落も混在。急激な難易度段差を避けるため段階間は補間。

## 生成アルゴリズム
到達時刻を基準に先のイベントを生成し、加速を積分した距離へ変換する。各イベントは一つの箱または穴を持ち、奥行きを含めて前後イベントと重ならない。

1. 距離に応じた範囲から次の到達間隔を抽選。
2. 同じ側を維持・中央寄り・反対側へ切り返しを混ぜ、安全通路の位置を抽選。連続の大きな切り返しは抑制。
3. 任意幅・任意位置の障害物を作り、左右に残る通路をrunner判定＋通路余裕ぶん縮め、runner中心が通れる区間を算出。
4. その区間上に、前イベントの安全位置から「前イベント退出〜次イベント進入」の時間内で到達できる安全位置があるかを確認。最大横速度に加え操作余裕0.18秒を確保。
5. 不成立なら再抽選。規定回数で成立しなければ、前の安全位置を維持できる端寄りの小さな箱を生成。
6. 各障害物に検証用の安全位置を保持。これは画面には表示しない。安全位置同士を空白区間内で接続し、障害物通過中は維持することで通れる経路を構成する。

これは「正しい進路を選べば通れる」保証であり、プレイヤーが任意の位置にいても救済される保証ではない。終盤は先読みを要求する。奈落の長さも検証時間に含め、上を横切って次へ移動する解は許可しない。

## 判定と時間管理
120Hz固定ステップ。前進距離は時間積分から求める。箱はrunnerの前後・左右の体積と追加の横余白で接触。奈落は足元が欠けた区間に入ったら落下。生成上は奈落にも全身が通れる幅を確保するため保守的な通路判定を使う。

タブ非表示・画面回転・長い処理停止では自動停止し、再開ボタンで戻す。停止中の時間は距離へ加算しない。保存はlocalStorageのベストのみ。保存不可でもゲームは続行する。

## 画面と表現
開始画面はSimple Runと再生アイコンだけ。プレイ中は上中央の距離のみ。停止時は再生アイコン。リザルトは距離・BEST・再試行アイコン。押せる領域は最低64px、セーフエリアを考慮する。

白い関節マネキン、灰色の箱、白灰色のコース。奈落は床メッシュを切り欠き、暗い内側と断面で識別。背景は淡い灰色。薄い床目地が前進速度の手掛かりになる。カメラは中央固定で横移動に追従しない。生成画像は素材に使用しない。キャラはQuaterniusの人型モデルと走行アニメーションを加工したGLB、コースと障害物はコードで生成する3D形状で描く。

## 構成
Vite + Three.js。バックエンド・外部画像なし。設定、生成・判定、3D描画と入力を分離。依存はロックファイルで固定。ビルドは相対パスでGitHub Pagesのサブパスに対応。

## 人型・光・速度の改訂 v0.2（2026-11-08）
- 球体の組み合わせを廃止し、CC0人型メッシュに置換。顔の凹凸・眉・眼を除き、細身の白いマネキンに加工。
- UALのJog / Sprintを素体へオフラインでリターゲットし、GLBに収録。速度11〜17でブレンドし、速度に合わせて歩調も調整。横移動による旋回はしない。
- 素材の正面は+Zのため、表示モデルをY軸に180度回転。進行方向の-Zを正面にする。初期化や転倒の回転とは別グループに保持。
- 主光源はrunnerの左後上方。環境光を弱めて箱の手前面・左面・上面の差を出す。箱は明るい灰色、奈落の側壁は青灰色、底は暗色。奈落の四方に側壁を置き、奥側の壁も同じ主光源で照らす。
- 加速度を0.12から0.4へ変更。上限20は維持。到達時間を100秒から30秒へ短縮。距離積分と逆関数、生成処理も同じ設定を参照。

## 入力・速度・距離表示の改訂 v0.3
- 速度は v(t) = min(40, 8 + 0.4t)。開始8、40秒で24、80秒で40。以降40を維持。80秒時点の距離は1920m。
- 横移動の速度制限と追従処理を廃止。ポインタの画面移動量と、runner胴体の画面移動量を1:1に変換して即時反映。カメラの投影から換算するため端末幅や開始カメラにも対応。
- 端で指を動かし続けた後も、反対へ動かせば即座に戻る。指を離した時点の位置を維持し、惰性は生じない。
- 横移動の線分全体にも衝突判定を行い、直接入力で箱や奈落をすり抜けないようにする。まとめられたPointerEventも順番に処理。
- 生成に使う5.4/秒は、操作上限ではなく、人間が無理なく横断する想定速度として保守的に残す。
- 距離表示を26pxから38〜48pxに拡大。画面上端から、霧の中へ消えるコース先端付近へ移動。カメラと速度に合わせて配置する。

検証：iPhone 14相当のブラウザでポインタを60px動かし、runnerの投影座標も195px→255px（60px）と即時追従することを確認。距離表示は390px幅で39px、霧のコース先端付近へ配置。テスト5件成功。

## 配置パターンの改訂 v0.4

### 速度
`v(t) = min(70, 8 + (62 / 120) × t)`。120秒で70に到達し、それ以降は70を維持。120秒時点の走行距離は4680m。操作感と距離表示はv0.3を維持。

### 進路を先に決める生成
一つの到達時刻に対応する「配置行」を生成し、各行は1〜2個の障害物を持つ。左右どこにrunnerを通したいかを先に決め、その通路の外側を箱や奈落で塞ぐ。

| パターン | 成熟後の抽選割合 | 挙動 |
|---|---:|---|
| switch | 55% | 前の安全位置と逆の端へ移動。通路幅は約1.4から1.08へ縮む |
| narrow | 25% | 逆側の狭い通路へ合わせる。通路幅は約1.01から0.84へ縮む |
| gate | 15% | 両側を塞ぎ、中央付近の隙間を抜ける。通路中心は±0.35で変化 |
| rest | 5% | 前の安全位置を維持できる、小さな内側の障害物 |

最初の2行は箱のみ。80〜400mでパターンの種類を徐々に解禁する。中央の隙間は1.08前後から0.84前後まで縮む。最小通路は肩幅の約1.4倍。両側障害物の接触判定と余裕を左右に確保した上で、中心位置に幅を残すための値。

- 両側配置は箱＋箱、奈落＋奈落、箱＋奈落、奈落＋箱を混ぜる。
- 通常・狭い通路・両側配置は、安全位置を前から最低0.55移動させる。
- 直近3行すべてで通れる共通の安全位置がある候補は却下。休憩パターンも連発しない。
- 不成立時は最大48回まで候補を試し、最後は逆側へ動く通常配置を使う。邪魔にならない小箱への救済は廃止。
- 次の安全位置までの移動時間と0.18秒の余裕を確保。抽選した間隔が短すぎたら、その難易度帯の上限以内で必要な分だけ延ばす。
- 通路は障害物の判定を結合した後で確認。箱は半幅0.30＋判定余白0.03＋通路余裕0.06を使って膨張し、奈落にも生成時は同じ保守的な余白を使う。
- 各行の最長の障害物を抜けるまで、その行の安全位置を保持する。箱だけ先に終わっても奈落の上を横断する経路は採用しない。

### 形と床
箱の奥行きは0.8〜1.5で固定範囲。奈落は速度×0.16〜0.26秒を基準に1.4〜5.5へ制限する。高速でも箱が長い壁に変わらない。

通常と狭い通路は、片端まで障害物で塞ぐため奈落もコース端までえぐれる。休憩配置には端に接しない穴も混ざる。端に接する穴は、外側の側壁と縁のラインを作らず、コースごと欠けた形にする。

床は全ての奈落の前後端で区間に分割し、同時に存在する穴の和集合を差し引く。両側が奈落でも中央の床を一度だけ生成し、別の穴を床で埋め戻さない。箱との混在も同じ処理で描く。

- 両側配置4種類が出ること、端に接する奈落が出ることを確認。
- 同じ奥行きの両側奈落と、異なる奥行きの奈落の床区間を検証。
- 成熟した配置の標本では、switch約57%、narrow約25%、gate約14%、rest約5%。不成立候補の除外で抽選比率から多少変化する。
- 平均安全位置移動量は約1.70（キャラ幅の約2.8倍）。前の位置を保つ休憩は約4.7%。

## 種類の連続制限 v0.5
箱だけ、奈落だけの配置行は最大3連続まで。同時に出る箱＋箱や奈落＋奈落は、その種類の配置1回として数える。箱＋奈落の混在は連続をリセット。3連続した後は、単独配置では反対の種類を選び、両側配置では同じ種類だけの組を候補から外す。候補再抽選やフォールバックにも適用する。最初の箱2回もカウントに含める。20万配置行の既存検証に、種類の4連続がないことの検証を追加。

## 手応え・リズム・記録の改訂 v0.6

### ギリギリ回避
障害物に並んでいる間の最小クリアランスを追跡し、判定から0.14以内を接触せず抜け切った時だけ、短い風切り音と0.16秒の薄い残像を出す。箱と奈落では音の高さ・長さを変える。加点や文字は出さない。同じ障害物では1回だけ、同時配置でも0.22秒のクールダウンで鳴りすぎを防ぐ。

残像は独立した骨格を持つ2体分のプールを再利用し、ポーズを写して薄く消す。形状は本体と共有し、新しいGLBを読み込まない。音はWeb Audioでローカル合成。スタート・再開・タッチのユーザー操作でAudioContextを作成・再開し、使えない端末では無音で続行する。BGMとボイスは追加しない。

### 配置の短いリズム
400m以降、ときどき3配置のセットを挟む。「左右切り返し3回」と「左右切り返し2回から中央通路へ」の2種類。セット終了後5〜9秒は次の短いセットを始めない。左右反転と障害物の種類は既存の生成に委ね、同じ種類最大3連続・通路・移動時間の制約を維持する。

### 難所と直後の休息
900m以降、4配置の難所を解禁。「左右切り返し3配置 → 中央の狭い通路」の順。大きな切り返し（横移動1.2以上）が最低2回入り、最後は幅1.0未満の両側通路になる。間隔は0.6〜0.9秒で、間に合うことを検証する。

最後の難所配置から、次の障害物の到達までを1.3〜1.6秒に広げる。速度は落とさない。休息は難所の直後にだけ追加し、通常のランダムな空白としては生成しない。難所を抜け終えてから20〜35秒は次を開始しない。短いリズムセットと重ねず、予告やクリアの文字は出さない。

### 自己ベスト地点
Run開始時の自己ベストを固定し、その距離の床に薄い暖灰色の線を引く。自己ベスト0では表示しない。奈落が重なる場合は残る床の範囲にだけ描く。通過時に小さな音を一度鳴らす。プレイ中の距離表示以外に新しいUIは増やさない。

### 失敗演出
箱では走っていた姿勢からそのまま前へ倒れ、わずかに弾む。奈落では落ち始めてから0.28秒だけ走行アニメーションを続け、走る足のまま落ちる。音は短く控えめ。どちらも0.9秒後に既存リザルトへ移る。リトライ導線は維持する。

### 検証
既存の20万配置行の通過可能性・3連続制限の検証に加え、4配置の難所、大きな切り返しの回数、狭い最終通路、休息との対応、20秒以上の再登場間隔を検証。回避判定は通過前・接触時・遠い回避で発火せず、抜け切った後に一度だけ発火することを検証する。

Web Audio再開は https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/resume 、骨格の残像複製は https://threejs.org/docs/pages/module-SkeletonUtils.html のAPIに沿って実装。
